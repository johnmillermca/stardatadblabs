How a role reaches a service
  1. Owner or Admin sets levels in Members → console backend creates or updates one ZITADEL authorization.
  2. On the next token, ZITADEL calls the stardata-claims Action (preaccesstoken) which adds the short claims.
  3. Each service reads its own claim: StarData proxy doris_role, Kafka kafka_role, Grafana monitoring_role…
  4. Access tokens live 10 minutes, so changes reach every service within 10 minutes.
