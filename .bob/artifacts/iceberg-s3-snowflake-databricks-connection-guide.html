1. Architecture Overview

All three engines — Spark, Snowflake, and Databricks — read the same Parquet files on S3. Spark is the primary write engine. Snowflake reads via an IAM-authenticated External Volume. Databricks reads via PyIceberg's S3 FileSystem catalog, then materialises to Delta for SQL access.

Spark (write) Snowflake (read) Databricks (read) │ │ │ │ Iceberg REST catalog │ EXTERNAL VOLUME │ PyIceberg SqlCatalog │ (Apache Polaris) │ (IAM role → S3) │ (S3 filesystem scan) ▼ ▼ ▼ ┌───────────────────────────────────────────────────────────┐ │ Amazon S3 (us-east-2) │ │ s3://<YOUR-BUCKET>/warehouse/<namespace>/<table>/ │ │ · data/ Parquet files (Snappy, ~2.56 MB each) │ │ · metadata/ *.metadata.json *.avro (manifests) │ └───────────────────────────────────────────────────────────┘

Part A — Create the Iceberg Table with Spark

This part covers creating the Iceberg table via a PySpark session (e.g., JupyterHub). Skip to Part B if your table already exists.

1
Fetch credentials from secrets manager

Retrieve the Polaris service-account credentials and S3 keys from your secrets store. In this platform, a helper reads them from OpenBao:

import urllib.request, json OPENBAO_ADDR = "http://<OPENBAO-HOST>:<PORT>" OPENBAO_TOKEN = REDACTED — get from secrets manager def _bao(path): req = urllib.request.Request( f"{OPENBAO_ADDR}/v1/{path}", headers={"X-Vault-Token": OPENBAO_TOKEN} ) return json.loads(urllib.request.urlopen(req, timeout=10).read())["data"]["data"] pol = _bao("secret/data/platform/polaris") s3 = _bao("secret/data/platform/s3") print("Credentials loaded")
2
Start Spark session with Polaris REST catalog

Configure the Iceberg Spark extensions and point spark.sql.catalog.polaris at the REST catalog endpoint:

from pyspark.sql import SparkSession import os, socket DRIVER_IP = os.environ.get("SPARK_LOCAL_IP", socket.gethostbyname(socket.gethostname())) POLARIS_URI = "http://<POLARIS-HOST>/api/catalog" spark = ( SparkSession.builder .master("spark://<SPARK-MASTER>:<PORT>") .appName("iceberg-table-setup") .config("spark.sql.extensions", "org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions") # ── Iceberg REST catalog ────────────────────────────────────────────── .config("spark.sql.catalog.polaris", "org.apache.iceberg.spark.SparkCatalog") .config("spark.sql.catalog.polaris.type", "rest") .config("spark.sql.catalog.polaris.uri", POLARIS_URI) .config("spark.sql.catalog.polaris.credential", REDACTED — pol['spark_svc_id'] + ':' + pol['spark_svc_secret']) .config("spark.sql.catalog.polaris.scope", "PRINCIPAL_ROLE:ALL") .config("spark.sql.catalog.polaris.warehouse", "<CATALOG-NAME>") # ── S3A filesystem ──────────────────────────────────────────────────── .config("spark.hadoop.fs.s3a.impl", "org.apache.hadoop.fs.s3a.S3AFileSystem") .config("spark.hadoop.fs.s3a.access.key", REDACTED — s3['access_key']) .config("spark.hadoop.fs.s3a.secret.key", REDACTED — s3['secret_key']) .config("spark.hadoop.fs.s3a.endpoint", "https://s3.<REGION>.amazonaws.com") .config("spark.hadoop.fs.s3a.path.style.access","true") .getOrCreate() ) spark.sparkContext.setLogLevel("WARN") print("Spark", spark.version, "connected")
3
Create the Iceberg table

Run DDL via Spark SQL. Replace <namespace>, <table>, and columns with your values:

CATALOG = "polaris" NAMESPACE = "<namespace>" # e.g. "lakehouse" TABLE = "<table>" # e.g. "orders" BUCKET = "<YOUR-BUCKET>" spark.sql(f"CREATE NAMESPACE IF NOT EXISTS {CATALOG}.{NAMESPACE}") spark.sql(f""" CREATE TABLE IF NOT EXISTS {CATALOG}.{NAMESPACE}.{TABLE} ( id BIGINT, event_type STRING, ts TIMESTAMP -- add your columns here ) USING iceberg PARTITIONED BY (hours(ts)) TBLPROPERTIES ( 'write.format.default' = 'parquet', 'write.parquet.compression-codec' = 'snappy', 'write.target-file-size-bytes' = '2684354' ) LOCATION 's3a://{BUCKET}/warehouse/{NAMESPACE}/{TABLE}' """) spark.sql(f"DESCRIBE EXTENDED {CATALOG}.{NAMESPACE}.{TABLE}").show(truncate=False)
4
Write initial data

Snowflake requires at least one committed Iceberg snapshot before registration. Load data now:

# Append from a DataFrame df.writeTo(f"{CATALOG}.{NAMESPACE}.{TABLE}") \ .option("write.target-file-size-bytes", "2684354") \ .append() spark.sql(f"SELECT COUNT(*) FROM {CATALOG}.{NAMESPACE}.{TABLE}").show() spark.stop() # ← always stop to release cluster resources
Part B — Connect to Snowflake

Snowflake reads Iceberg metadata directly from S3 using an IAM role (CATALOG = 'OBJECT_STORE'). No Polaris connectivity is required. All steps run in the Snowflake SQL Worksheet as ACCOUNTADMIN.

Do NOT recreate the External Volume if one already exists. Each CREATE OR REPLACE EXTERNAL VOLUME generates a new ExternalId, which requires updating the AWS IAM role trust policy again.
1
One-time: Create AWS IAM Role for Snowflake (AWS Console)

This is done once per Snowflake account. Create an IAM role and trust it for Snowflake's AWS account:

FieldValue
Role nameREDACTED — your-snowflake-iceberg-role
Trust principal (AWS account)REDACTED — Snowflake's AWS IAM user ARN (from DESCRIBE EXTERNAL VOLUME)
Trust ExternalIdREDACTED — from DESCRIBE EXTERNAL VOLUME after creation
Inline policy permissionss3:GetObject, s3:GetObjectVersion, s3:PutObject, s3:DeleteObject, s3:DeleteObjectVersion, s3:ListBucket, s3:GetBucketLocation on your S3 bucket + prefix
2
One-time: Create External Volume in Snowflake
USE ROLE ACCOUNTADMIN; CREATE OR REPLACE EXTERNAL VOLUME iceberg_s3_vol STORAGE_LOCATIONS = ( ( NAME = 'iceberg-s3-<REGION>' STORAGE_PROVIDER = 'S3' STORAGE_BASE_URL = 's3://<YOUR-BUCKET>/warehouse/' STORAGE_AWS_ROLE_ARN = REDACTED — arn:aws:iam::<AWS-ACCOUNT-ID>:role/<ROLE-NAME> ) ) ALLOW_WRITES = TRUE; -- After creation, retrieve the auto-generated trust values: DESCRIBE EXTERNAL VOLUME iceberg_s3_vol; -- Copy STORAGE_AWS_IAM_USER_ARN and STORAGE_AWS_EXTERNAL_ID -- → Update the IAM role trust policy in AWS Console with these values
3
One-time: Create Catalog Integration
CREATE OR REPLACE CATALOG INTEGRATION iceberg_object_store CATALOG_SOURCE = OBJECT_STORE TABLE_FORMAT = ICEBERG ENABLED = TRUE;
4
Find the latest Iceberg metadata file on S3

Before registering, locate the most recent metadata.json snapshot:

# From a shell with AWS CLI configured: aws s3 ls s3://<YOUR-BUCKET>/warehouse/<namespace>/<table>/metadata/ \ --region <REGION> | sort | tail -1 # Copy the filename, e.g.: 00011-abc123.metadata.json
5
Register the Iceberg table in Snowflake

Create the database/schema if they don't exist, then register the table pointing at the metadata file from Step 4:

USE ROLE ACCOUNTADMIN; CREATE DATABASE IF NOT EXISTS <DATABASE_NAME>; USE DATABASE <DATABASE_NAME>; CREATE SCHEMA IF NOT EXISTS <SCHEMA_NAME>; USE SCHEMA <SCHEMA_NAME>; -- BASE_LOCATION is relative to the External Volume STORAGE_BASE_URL -- i.e. s3://<YOUR-BUCKET>/warehouse/ + <namespace>/<table>/ CREATE OR REPLACE ICEBERG TABLE <table_name> CATALOG = 'iceberg_object_store' EXTERNAL_VOLUME = 'iceberg_s3_vol' BASE_LOCATION = '<namespace>/<table>/' METADATA_FILE_PATH = 'metadata/<filename-from-step-4>.metadata.json'; -- Verify row count SELECT COUNT(*) FROM <table_name>;
6
Schedule automatic hourly metadata refresh

When Spark writes new data, the metadata pointer on S3 advances. This Snowflake Task re-reads it every hour:

CREATE OR REPLACE TASK refresh_<table_name> WAREHOUSE = COMPUTE_WH SCHEDULE = 'USING CRON 0 * * * * UTC' COMMENT = 'Hourly Iceberg metadata refresh via S3 OBJECT_STORE' AS ALTER ICEBERG TABLE <DATABASE_NAME>.<SCHEMA_NAME>.<table_name> REFRESH; -- Tasks are created SUSPENDED — explicitly resume: ALTER TASK refresh_<table_name> RESUME; -- Confirm state = started SHOW TASKS LIKE 'refresh_<table_name>';
7
Grant RBAC access
-- Grant read access to your roles GRANT USAGE ON DATABASE <DATABASE_NAME> TO ROLE <engineer_role>; GRANT USAGE ON SCHEMA <DATABASE_NAME>.<SCHEMA_NAME> TO ROLE <engineer_role>; GRANT SELECT ON TABLE <DATABASE_NAME>.<SCHEMA_NAME>.<table_name> TO ROLE <engineer_role>; GRANT USAGE ON DATABASE <DATABASE_NAME> TO ROLE <analyst_role>; GRANT USAGE ON SCHEMA <DATABASE_NAME>.<SCHEMA_NAME> TO ROLE <analyst_role>; GRANT SELECT ON TABLE <DATABASE_NAME>.<SCHEMA_NAME>.<table_name> TO ROLE <analyst_role>;
8
Verify end-to-end
-- Match row count against Spark SELECT COUNT(*) FROM <DATABASE_NAME>.<SCHEMA_NAME>.<table_name>; -- Force an immediate out-of-schedule refresh if needed ALTER ICEBERG TABLE <DATABASE_NAME>.<SCHEMA_NAME>.<table_name> REFRESH; -- Check last 5 task runs SELECT name, state, scheduled_time, completed_time, error_code, error_message FROM TABLE(INFORMATION_SCHEMA.TASK_HISTORY( SCHEDULED_TIME_RANGE_START => DATEADD('hour', -24, CURRENT_TIMESTAMP), TASK_NAME => 'refresh_<table_name>' )) ORDER BY scheduled_time DESC LIMIT 5;
Re-registration after many snapshots: If the registered metadata snapshot drifts too far, the hourly refresh may fail. Fix by re-running Step 5 with the latest metadata file path, then resume the task.
Part C — Connect to Databricks

Databricks reads Iceberg data using PyIceberg's S3 FileSystem catalog — no REST catalog or Polaris needed. Data is materialised into a Delta table and exposed as a SQL view for use in the SQL console or notebooks.

Works on Databricks Free / Community Edition. The Secrets API (dbutils.secrets) is not available on the free tier — use notebook widgets to supply credentials instead.
1
Create a cluster

Compute → Create cluster → Single Node → DBR 14+ LTS (or 16.x). A single-node cluster is sufficient for reads.

2
Cell 1 — Install PyIceberg (run first, wait for restart)
%pip install \ "pyiceberg[s3fs,pyarrow,sql-sqlite]>=0.7.0" \ "sqlalchemy>=1.4.0,<3.0.0" \ "botocore>=1.40.45,<1.41.0" \ "boto3>=1.40.45,<1.41.0" \ --quiet dbutils.library.restartPython() # restart kernel so packages are importable
Pin botocore to >=1.40.45,<1.41.0 — without the pin, PyIceberg pulls a newer botocore that conflicts with the boto3 version bundled in Databricks Free Edition.
3
Cell 2 — Credential widgets (free-tier alternative to dbutils.secrets)
dbutils.widgets.text("s3_access_key", "", "S3 Access Key (AKIA...)") dbutils.widgets.text("s3_secret_key", "", "S3 Secret Key") print("Fill in the widgets above, then run Cell 3.")
4
Cell 3 — Configuration
import os WAREHOUSE_ROOT = "s3://<YOUR-DATABRICKS-BUCKET>/iceberg/warehouse/" S3_REGION = "<REGION>" # e.g. us-east-2 S3_ENDPOINT = f"https://s3.{S3_REGION}.amazonaws.com" CATALOG_DB_PATH = "/tmp/iceberg_catalog.db" # rebuilt each run # Read from widgets (values never appear in logs) S3_ACCESS_KEY = dbutils.widgets.get("s3_access_key") S3_SECRET_KEY = dbutils.widgets.get("s3_secret_key") os.environ["AWS_ACCESS_KEY_ID"] = S3_ACCESS_KEY os.environ["AWS_SECRET_ACCESS_KEY"] = S3_SECRET_KEY os.environ["AWS_DEFAULT_REGION"] = S3_REGION print(f"Warehouse : {WAREHOUSE_ROOT}") print(f"Region : {S3_REGION}") print(f"Key : {S3_ACCESS_KEY[:6]}...{S3_ACCESS_KEY[-4:]} ✅")
5
Cell 4 — Build the PyIceberg SqlCatalog
from pyiceberg.catalog.sql import SqlCatalog if os.path.exists(CATALOG_DB_PATH): os.remove(CATALOG_DB_PATH) catalog = SqlCatalog( "my_catalog", **{ "uri": f"sqlite:///{CATALOG_DB_PATH}", "warehouse": WAREHOUSE_ROOT, "s3.access-key-id": S3_ACCESS_KEY, "s3.secret-access-key": S3_SECRET_KEY, "s3.region": S3_REGION, "s3.endpoint": S3_ENDPOINT, "s3fs.key": S3_ACCESS_KEY, "s3fs.secret": S3_SECRET_KEY, "s3fs.endpoint_url": S3_ENDPOINT, }, ) print("PyIceberg SqlCatalog ready")
6
Cell 5 — Auto-discover and register all Iceberg tables from S3

Walks the warehouse path and registers every table found under <db>/<table>/metadata/:

import s3fs fs = s3fs.S3FileSystem( key=S3_ACCESS_KEY, secret=S3_SECRET_KEY, endpoint_url=S3_ENDPOINT, client_kwargs={"region_name": S3_REGION}, ) warehouse_bare = WAREHOUSE_ROOT.replace("s3://", "", 1).rstrip("/") registered = [] for db_path in fs.ls(warehouse_bare, detail=False): db_name = db_path.rstrip("/").split("/")[-1] try: catalog.create_namespace((db_name,)) except: pass for tbl_path in fs.ls(db_path, detail=False): tbl_name = tbl_path.rstrip("/").split("/")[-1] meta_prefix = tbl_path.rstrip("/") + "/metadata" identifier = (db_name, tbl_name) try: meta_files = sorted( [f for f in fs.ls(meta_prefix, detail=True) if f["name"].endswith(".metadata.json")], key=lambda f: f.get("LastModified", 0), reverse=True ) if not meta_files: continue latest = "s3://" + meta_files[0]["name"] try: catalog.drop_table(identifier) except: pass catalog.register_table(identifier, latest) registered.append(f"{db_name}.{tbl_name}") except: pass print(f"Registered {len(registered)} table(s):") for t in registered: print(f" {t}")
7
Cell 6 — Read a table as a Pandas DataFrame or Spark SQL view
READ_NAMESPACE = "<namespace>" # e.g. "lakehouse_db" READ_TABLE = "<table>" # e.g. "customers" ROW_LIMIT = 1000 # set None to read all tbl = catalog.load_table((READ_NAMESPACE, READ_TABLE)) arrow_tbl = tbl.scan(limit=ROW_LIMIT).to_arrow() df = arrow_tbl.to_pandas() print(f"Rows: {len(df):,} Columns: {list(df.columns)}") display(df)

To expose as a queryable SQL view in the Databricks SQL console:

DELTA_PATH = f"dbfs:/snapshots/{READ_NAMESPACE}/{READ_TABLE}" VIEW_NAME = f"{READ_NAMESPACE}__{READ_TABLE}__live" (spark.createDataFrame(df).write .format("delta").mode("overwrite") .option("overwriteSchema", "true") .save(DELTA_PATH)) spark.read.format("delta").load(DELTA_PATH) \ .createOrReplaceTempView(VIEW_NAME) print(f"SQL view ready: SELECT * FROM {VIEW_NAME}") spark.sql(f"SELECT * FROM {VIEW_NAME}").display()

Cell 7 — Snapshot history & time travel
import datetime as dt tbl = catalog.load_table((READ_NAMESPACE, READ_TABLE)) print(f"Snapshot history — {READ_NAMESPACE}.{READ_TABLE}") for entry in tbl.history(): snap = tbl.snapshot_by_id(entry.snapshot_id) if snap is None: continue ts = dt.datetime.utcfromtimestamp(snap.timestamp_ms / 1000).strftime("%Y-%m-%d %H:%M:%S UTC") summary = snap.summary.additional_properties if snap.summary else {} print(f" id={snap.snapshot_id} committed={ts} op={summary.get('operation','?')} " f"total-records={summary.get('total-records','?')}") # Time-travel to a specific snapshot: # df = catalog.load_table((ns, tbl)).scan(snapshot_id=<id>).to_arrow().to_pandas()

After each Spark write, both Snowflake and Databricks need to be refreshed to see new data.

Troubleshooting
Snowflake returns 0 rows after Spark writes new data
  1. Run a manual refresh: ALTER ICEBERG TABLE <DB>.<SCHEMA>.<table> REFRESH;
  2. Check the task state: SHOW TASKS LIKE 'refresh_<table>'; — must be started
  3. If suspended: ALTER TASK refresh_<table> RESUME;
Snowflake EXTERNAL VOLUME — STS AssumeRole denied
  1. Run DESCRIBE EXTERNAL VOLUME iceberg_s3_vol; — copy STORAGE_AWS_IAM_USER_ARN and STORAGE_AWS_EXTERNAL_ID.
  2. Go to AWS IAM → your Snowflake IAM role → Trust relationships.
  3. Verify the principal ARN and ExternalId match exactly what Snowflake generated. Update if they differ.
  4. Never recreate the External Volume — each CREATE OR REPLACE generates a new ExternalId.
PyIceberg cannot list S3 path / credential error on Databricks
  1. Ensure the credential widgets in Cell 2 are filled in before running Cell 3+.
  2. Confirm S3 bucket and prefix are correct — check WAREHOUSE_ROOT includes the trailing slash.
  3. Verify the IAM user/key has s3:ListBucket and s3:GetObject on the bucket.
  4. Re-run Cell 1 (%pip install) if you attached to a new cluster — packages must be reinstalled per session.
Snowflake metadata drift — refresh fails after many Spark snapshots

Re-register the table pointing at the latest metadata file:

# 1. Find latest metadata file (from a machine with AWS CLI): aws s3 ls s3://<YOUR-BUCKET>/warehouse/<namespace>/<table>/metadata/ \ --region <REGION> | sort | tail -1 # 2. Re-register in Snowflake: USE ROLE ACCOUNTADMIN; USE DATABASE <DATABASE_NAME>; USE SCHEMA <SCHEMA_NAME>; CREATE OR REPLACE ICEBERG TABLE <table_name> CATALOG = 'iceberg_object_store' EXTERNAL_VOLUME = 'iceberg_s3_vol' BASE_LOCATION = '<namespace>/<table>/' METADATA_FILE_PATH = 'metadata/<latest-file>.metadata.json'; ALTER TASK refresh_<table_name> RESUME;
botocore / boto3 version conflict on Databricks

Without pinning, PyIceberg pulls botocore>=1.43 which conflicts with the DBR-bundled boto3. Always use:

%pip install "botocore>=1.40.45,<1.41.0" "boto3>=1.40.45,<1.41.0" --quiet
